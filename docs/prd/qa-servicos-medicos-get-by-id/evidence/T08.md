# T08 — GET com header Authorization mal formado (sem prefixo Bearer)

## Caso A — token cru, sem prefixo "Bearer "

### Comando executado

```
curl -s -i -X GET "http://localhost:8080/v1/api/servicos-medicos/241760a1-efdc-44c6-b3c2-1f3a64013fe4" \
  -H "Authorization: eyJhbGciOiJIUzUxMiJ9...[REDIGIDO]" \
  -H "Accept: application/json"
```

### Resposta crua

```
HTTP/1.1 403
X-Content-Type-Options: nosniff
X-XSS-Protection: 0
Cache-Control: no-cache, no-store, max-age=0, must-revalidate
Pragma: no-cache
Expires: 0
X-Frame-Options: DENY
Content-Length: 0
Date: Sat, 15 Aug 2026 15:16:34 GMT

(corpo vazio)
```

## Caso B — esquema "Basic" em vez de "Bearer"

### Comando executado

```
curl -s -i -X GET "http://localhost:8080/v1/api/servicos-medicos/241760a1-efdc-44c6-b3c2-1f3a64013fe4" \
  -H "Authorization: Basic xxx" \
  -H "Accept: application/json"
```

### Resposta crua

```
HTTP/1.1 403
X-Content-Type-Options: nosniff
X-XSS-Protection: 0
Cache-Control: no-cache, no-store, max-age=0, must-revalidate
Pragma: no-cache
Expires: 0
X-Frame-Options: DENY
Content-Length: 0
Date: Sat, 15 Aug 2026 15:16:34 GMT

(corpo vazio)
```

## Avaliação

- Ambos os casos retornam **`403`** — igual ao de T04, confirmando que o filtro não
  distingue header mal formado de token ausente.

**RESULTADO: APROVADO**
