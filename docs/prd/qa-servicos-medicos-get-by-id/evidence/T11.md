# T11 — GET com id vazio (barra final)

## Comando executado

```
curl -s -i -X GET "http://localhost:8080/v1/api/servicos-medicos/" \
  -H "Authorization: Bearer eyJhbGciOiJIUzUxMiJ9...[REDIGIDO]" \
  -H "Accept: application/json"
```

## Resposta crua

```
HTTP/1.1 404
X-Content-Type-Options: nosniff
X-XSS-Protection: 0
Cache-Control: no-cache, no-store, max-age=0, must-revalidate
Pragma: no-cache
Expires: 0
X-Frame-Options: DENY
Content-Type: application/problem+json
Transfer-Encoding: chunked
Date: Sat, 15 Aug 2026 15:17:19 GMT

{"detail":"No static resource v1/api/servicos-medicos.","instance":"/v1/api/servicos-medicos/","status":404,"title":"Not Found"}
```

## Avaliação

- Status real observado: **`404`**, com mensagem `"No static resource
  v1/api/servicos-medicos."` — confirma que a URL `/v1/api/servicos-medicos/` (barra
  final, sem id) **não** cai na rota de listagem `GET /v1/api/servicos-medicos` (sem
  barra) nem no `consultar(id)`. Em vez disso, o Spring MVC trata como um pedido de
  recurso estático não encontrado, porque não há mapeamento de rota para esse path exato
  com barra final.

**RESULTADO: APROVADO** (comportamento observado documentado; não é o comportamento intuitivo de "cair na listagem", mas é consistente com roteamento padrão do Spring MVC)
