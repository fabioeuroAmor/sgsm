# T18 — Observabilidade: log DEBUG do SQL disparado por GET

## Tentativas realizadas

1. Inspecionado `src/main/resources/application-dev.yaml` (somente leitura, não editado):
   confirma `logging.level.br.com.sgsm: DEBUG`, `org.hibernate.SQL: DEBUG`,
   `org.hibernate.orm.jdbc.bind: TRACE` — porém **não há appender de arquivo
   configurado** (nenhuma seção `logging.file` / `logging.pattern.file` / Logback
   `FileAppender` customizado encontrada em `application*.yaml`). O log vai só para
   console (stdout).
2. Busca em todo o diretório do projeto por arquivos `*.log`:
   `find /c/AmbienteDev/sgsm -iname "*.log"` → nenhum resultado (fora `.git/logs`, que
   não é log de aplicação).
3. Identificação do processo real da aplicação via
   `Get-CimInstance Win32_Process -Filter "Name = 'java.exe'"`: PID `3980`, classe
   principal `br.com.sgsm.SgsmApplication`, iniciado com
   `-javaagent:...idea_rt.jar=57632` — ou seja, processo lançado a partir de uma
   configuração de execução do IntelliJ IDEA, cujo stdout/stderr é capturado pela janela
   "Run" da IDE (console interno da IDE), não redirecionado para nenhum arquivo em disco.
4. Verificação de possíveis logs indiretos da IDE que pudessem conter a saída do console
   do processo filho: `C:\Users\re048720\AppData\Local\JetBrains\IntelliJIdea2025.3\log\idea.log`
   — inspecionado, contém apenas o log interno da própria IDE/plugins (inclusive linhas
   do próprio bridge do Claude Code), **não** o console redirecionado do processo
   `SgsmApplication`.

## Avaliação

Não foi possível obter uma linha de log real (crua) da aplicação para este item, porque:
- Não existe appender de arquivo configurado em nenhum profile de log da aplicação —
  toda a saída DEBUG vai só para o console do processo.
- O console do processo `SgsmApplication` (PID 3980) está anexado à janela "Run" do
  IntelliJ IDEA, um fluxo de saída que este subagente (execução via shell/bash headless,
  sem acesso à UI da IDE) não tem como capturar sem tocar em configuração/infraestrutura
  (o que está fora do escopo permitido) ou sem acesso à interface gráfica da IDE (fora do
  alcance das ferramentas disponíveis a este subagente).
- Nenhuma chamada foi simulada nem inferida por leitura de código para preencher esta
  lacuna, conforme a regra do plano.

**RESULTADO: NÃO TESTÁVEL NESTA RODADA** — motivo: ambiente não expõe um destino de log
capturável (nem arquivo, nem console acessível) para o processo real da aplicação a
partir das ferramentas disponíveis a este subagente. Não é uma falha do endpoint: as
requisições T01–T17 foram, comprovadamente, atendidas com sucesso pela aplicação real
(evidenciado pelos próprios status/corpos de resposta HTTP), mas a captura específica de
uma linha de log SQL fica pendente de decisão do responsável pela tarefa (ex.: reiniciar
a aplicação redirecionando stdout para arquivo, ou acessar a janela "Run" da IDE
manualmente).
