# T09-NEG — Decisão de negócio: rota sem role específica

## Evidência

Reutiliza a evidência de T01 (`evidence/T01.md`): `GET
/v1/api/servicos-medicos/241760a1-efdc-44c6-b3c2-1f3a64013fe4` com `TOKEN_VALIDO`
(`perfil: MEDICO`, `roles: ["MEDICO"]`) retornou `200` com o corpo completo do recurso,
confirmando acesso de leitura concedido a um usuário autenticado com perfil `MEDICO`,
sem que a rota `/v1/api/servicos-medicos/**` exija explicitamente essa role em
`SecurityConfig` (diferente de `/v1/api/servicos/**`).

## Nota para o responsável pela tarefa

Achado de leitura de código (não testado ao vivo neste item, apenas confirmado que
`MEDICO` funciona): a rota cai em `.anyRequest().authenticated()`, portanto qualquer
perfil autenticado (inclusive `PACIENTE`) teria acesso de leitura, e o claim
`permissions` do token nunca é lido pelo `JwtAuthFilter`. **Não testável nesta rodada**
para outros perfis (`PACIENTE`, `FUNCIONARIO`) por não haver token desses perfis
disponível. Fica registrado como decisão de negócio a ser confirmada pelo responsável:
é intencional que a leitura de `servicos-medicos` seja aberta a qualquer perfil
autenticado?

**RESULTADO: NÃO TESTÁVEL PARA OUTROS PERFIS (aceito como limitação de tokens
disponíveis) — evidência de MEDICO funcionando: ver T01**
